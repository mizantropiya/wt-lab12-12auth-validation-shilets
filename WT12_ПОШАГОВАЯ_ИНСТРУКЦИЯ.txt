ПОЛНАЯ ИНСТРУКЦИЯ WT-12 — ШИЛЕЦ ОЛЬГА, УИР-2
================================================

С ЧЕГО НАЧАТЬ (ПРОЕКТ В АРХИВЕ ПОЛНЫЙ)
1. Распакуйте zip полностью. Откройте папку wt-lab12-12auth-validation-shilets.
2. Убедитесь, что .NET SDK и Docker Desktop установлены. Запустите Docker Desktop.
3. Дважды щёлкните 01_START_WT12.cmd. Он сам запустит или создаст PostgreSQL,
   соберёт приложение и запустит локальный сайт.
4. Откройте http://localhost:5290/Login. Пользователь student / пароль 1234.
5. Чтобы получить скриншот списка миграций, откройте в отдельном окне
   02_CHECK_BUILD_AND_MIGRATIONS.cmd (при работающем Docker Desktop).
6. Не закрывайте окно работающего приложения, пока снимаете браузерные скриншоты.
7. Если откроется окно с ошибкой, сохраните его текст/скрин, не меняя исходники.

ГДЕ ВСТАВЛЯТЬ СКРИНШОТЫ
Используйте ваш ранее подготовленный Word-отчёт WT-12, он не нужен для запуска проекта.
В отчёте 15 блоков "ВСТАВИТЬ СКРИНШОТ СЮДА" и подписи рисунков 1-15.
Чтобы вставить изображение, на экране с нужным результатом нажмите Win+Shift+S,
выделите область, в Word удалите текст плейсхолдера, затем Ctrl+V.
Подписей к рисункам повторно не создавайте.
Скриншоты браузера делайте с адресной строкой. Пароли облачной БД не показывайте.

КОМАНДЫ ДЛЯ РУЧНОЙ ПРОВЕРКИ (если нужны)
В PowerShell в корне проекта при запущенном PostgreSQL:
  $env:ASPNETCORE_ENVIRONMENT = "Development"
  Remove-Item Env:DATABASE_URL -ErrorAction SilentlyContinue
  dotnet tool restore
  dotnet build
  dotnet tool run dotnet-ef database update
  dotnet tool run dotnet-ef migrations list

Не выполняйте migrations add AddUsers: миграция уже включена.

СПИСОК 15 СКРИНШОТОВ — ЧТО ОТКРЫТЬ И КУДА ВСТАВИТЬ

№1. «Рисунок 1 – Структура проекта WT-12».
  Откройте в Visual Studio файл wt-lab12-12auth-validation-shilets.sln.
  Справа в «Обозревателе решений» (Вид -> Обозреватель решений) разверните проект, Data, Models, Migrations, Pages и Accounts.
  Скриншот структуры дерева файлов. Вставьте перед подписью «Рисунок 1» в отчёте.

№2. «Рисунок 2 – Модель пользователя User».
  В Visual Studio откройте Models -> User.cs.
  Покажите Id, Login, Password, атрибуты [Required], [StringLength].
  Скрин кода -> рисунок №2.

№3. «Рисунок 3 – DbSet<User> и настройка таблицы Users».
  Откройте Data -> AppDbContext.cs.
  На одном скриншоте желательно показать DbSet<User> Users и modelBuilder.Entity<User>().
  Если не помещается, уменьшите масштаб текста редактора через Ctrl + колесо мыши вниз.
  Скрин -> рисунок №3.

№4. «Рисунок 4 – Миграция AddUsers».
  В PowerShell выполните: dotnet tool run dotnet-ef migrations list.
  Покажите название 20261028000100_AddUsers и отсутствие (Pending).
  Скрин PowerShell -> рисунок №4.

№5. «Рисунок 5 – Таблица Users в PostgreSQL».
  В PowerShell выполните:
  docker exec -it wt-lab8-postgres psql -U wt8_user -d wt_lab8
  В открывшейся строке wt_lab8=# выполните:
  SELECT "Id", "Login", "Password" FROM "Users" ORDER BY "Id";
  Покажите строку student / 1234 и имена столбцов.
  Скрин PowerShell -> рисунок №5. Затем напишите \q и Enter для выхода из psql.

№6. «Рисунок 6 – Настройка Session в Program.cs».
  Откройте Program.cs. Покажите AddDistributedMemoryCache(), AddSession(...) и UseSession().
  Если фрагменты не помещаются на 1 скрине, сделайте 2 небольших скриншота и вставьте оба в место №6.

НАЧИНАЯ С №7: сайт уже запущен через 01_START_WT12.cmd.
Оставьте окно запуска открытым! В браузере открывайте http://localhost:5290.
Если порт занят, проверьте, не запущена ли вторая копия WT-12.

№7. «Рисунок 7 – Страница входа /Login».
  В адресной строке браузера введите http://localhost:5290/Login и Enter.
  Ничего не вводите. Покажите поля Логин, Пароль и кнопку Войти.
  Скрин браузера с адресом /Login -> рисунок №7.

№8. «Рисунок 8 – Проверка пустой формы».
  Оставьте обе строки пустыми и нажмите «Войти».
  Должны появиться «Введите логин» и «Введите пароль».
  Скрин ошибок -> рисунок №8.

№9. «Рисунок 9 – Проверка длины логина и пароля».
  В поле Логин введите ab, в Пароль — 123, нажмите «Войти».
  Покажите «Логин должен содержать от 3 до 50 символов» и «Пароль должен содержать не менее 4 символов».
  Скрин -> рисунок №9.

№10. «Рисунок 10 – Неверные учётные данные».
  Введите Логин student и Пароль 9999, нажмите «Войти».
  Покажите «Неверный логин или пароль.»
  Скрин -> рисунок №10.

№11. «Рисунок 11 – Успешная авторизация и страница Profile».
  Введите student / 1234 и нажмите «Войти».
  Должен открыться адрес http://localhost:5290/Profile, в карточке видно student и «Выйти».
  Скрин -> рисунок №11.

№12. «Рисунок 12 – Выход пользователя».
  Нажмите «Выйти» на /Profile.
  Должен открыться /Login и появиться «Вы вышли из системы.»
  Скрин -> рисунок №12.

№13. «Рисунок 13 – Защита /Profile после выхода».
  После выхода прямо в адресной строке вручную наберите http://localhost:5290/Profile и нажмите Enter.
  Должно автоматически перенаправить обратно на http://localhost:5290/Login.
  Скрин со строкой адреса /Login -> рисунок №13.

№14. «Рисунок 14 – Работа банковских счетов после добавления авторизации».
  Откройте http://localhost:5290/Accounts/Index (или в верхнем меню нажмите «Счета»).
  Покажите карточки счетов, кнопки и меню «Войти», «Личный кабинет».
  Скрин -> рисунок №14. При желании отдельно проверьте создание/редактирование/удаление учебного счёта.

№15. «Рисунок 15 – GitHub-репозиторий WT-12».
  Откройте github.com и войдите под своим аккаунтом mizantropiya.
  Справа сверху нажмите «+» -> «New repository».
  Название: wt-lab12-12auth-validation-shilets. Выберите Public.
  ВАЖНО: НЕ включайте «Add a README file», .gitignore или лицензию.
  Нажмите «Create repository».
  В PowerShell в папке проекта выполните:
    git log --oneline
    git remote add origin https://github.com/mizantropiya/wt-lab12-12auth-validation-shilets.git
    git branch -M main
    git push -u origin main
  Если git remote add origin сообщает «remote origin already exists», используйте вместо неё:
    git remote set-url origin https://github.com/mizantropiya/wt-lab12-12auth-validation-shilets.git
  После push обновите GitHub (F5), раскройте Migrations, Pages, Models и покажите страницу репозитория.
  Скрин браузера с адресом GitHub -> рисунок №15.

ЧАСТЬ 4. КАК ЗАВЕРШИТЬ ОТЧЁТ
1. Убедитесь, что все 15 пустых блоков для изображений заполнены.
